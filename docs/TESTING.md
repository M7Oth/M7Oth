# الاختبارات ونتائجها — Testing

## 1. اختبارات الوحدة والتكامل (Vitest)
```bash
npm test                                                   # بدون قاعدة بيانات (يستخدم ملف JSON للخادم)
TEST_DATABASE_URL=postgres://fls:fls@localhost:5432/fls_test npm test   # الخادم على PostgreSQL 16 حقيقي
```
النتيجة في بيئة التطوير (PostgreSQL 16): **149/149 ناجحة** — 3 ملفات:

| الملف | ما يغطيه |
|---|---|
| `shared/test/work.test.ts` | 125 مهمة مونتاج مولّدة (5 صعوبات × 25 بذرة) قابلة للحل بعمليات المحرر فقط؛ العمل غير المنجز يفشل؛ القص الزائد يكسر «حافظ على بقية اللقطات»؛ الموشن يتحقق من التوقيت (تحريك مفتاح يفشل الشرط)؛ الجرافيك والثري دي لكل الصعوبات |
| `shared/test/engine.test.ts` | دورة كاملة مع دفع مرة واحدة، رفض التسليم والتسليم المكرر، التعديلات، الشراء ومنع الشراء المكرر/بدون رصيد، أثر المعالج والكرسي، الطاقة والنوم وتمرير الوقت، منع تداخل الأثاث، فشل المواعيد، المصاريف الأسبوعية، تقسيم أرباح التعاون، التدرج للمراحل 2→5 مع المستقلين والموظفين والمنسّق ومدير المشاريع |
| `server/test/multiplayer.test.ts` | خادم HTTP + WebSocket حقيقي: الحسابات، الدعوة والعضوية، رفض غير الأعضاء، مزامنة الحركة والتقدم، قبول متزامن لنفس العرض (واحد فقط ينجح)، إرسال نفس الإجراء مرتين، إسناد ومنع تنفيذ مهمة شخص آخر، توزيع الأرباح وإيداع حصة الصديق مرة واحدة، انقطاع الاتصال وإعادة إرسال الشراء دون تكراره، إعادة تشغيل الخادم واستمرار البيانات، تحويل أرباح التعاون مرة واحدة |

## 2. سيناريو المتصفح الكامل (E2E)
```bash
npm run build
node e2e/full-scenario.mjs          # يشغّل خادمًا خاصًا على 8899 مع ALLOW_DEV_CHEATS=1
```
يستخدم Playwright + Chromium مع WebGL (SwiftShader)، وسياقي متصفح منفصلين (جهازان) ضد خادم حقيقي.
النتيجة: **23/23 خطوة ناجحة** (`docs/e2e-results.json`، لقطات الشاشة في `docs/screenshots/`):

1. لاعب جديد ينشئ حسابًا وشخصية بتخصص المونتاج ويدخل غرفته.
2. يفتح «المشاريع» ويقبل العرض فيصبح نشطًا.
3. يضغط «اعمل عليها» → تمشي الشخصية للمكتب، تجلس، تقترب الكاميرا وتفتح الشاشة. ينفّذ طلبات العميل **عبر واجهة التايملاين فقط** (مؤشر التشغيل، القص، الحذف، التحريك، النص، القوائم) — التحقق المباشر 100%.
4. يسلّم المشروع، ينتهي التصدير، يقبله العميل (أو يطلب تعديلًا يُنفّذ ثم يُعاد التسليم) ويُدفع المبلغ.
5. يشتري معالجًا من المتجر: يُخصم المبلغ ويُركّب، وتقل مدة التصدير فعليًا (مثال من التشغيل: 77 → 57 دقيقة لعب).
6. الطاقة انخفضت بعد العمل؛ يأخذ استراحة على الكنبة.
7. ينشئ رمز دعوة؛ صديق من متصفح آخر ينشئ حسابه ويدخل الرمز ويظهر في نفس الغرفة، وحركته تصل للمضيف.
8. مشروع من مهمتين: كل لاعب يأخذ مهمة من لوحته وتظهر للآخر، ينفذان العمل في نفس الوقت، تسليم مكرر يُرفض من الخادم، اتفاق 50/50، الدفع يُقسّم (مثال: 880 → 440/440) وتصل حصة الصديق لحسابه.
9. الانتقال لمرحلة «فريلانسر محترف» من لوحة المسيرة، التعاقد مع مستقل لمهمة، فتح استوديو (الانتقال للمكتب)، توظيف أول موظف، النمو لوكالة، فتح قسم الموشن، توظيف منسّق ومدير مشاريع، ثم يوزّع مدير المشاريع مشروعًا واحدًا بين قسمي المونتاج والموشن تلقائيًا.
10. إغلاق المتصفحين وإعادة تشغيل الخادم بالكامل، ثم المتابعة من نفس الجهاز: المرحلة والموظفون والمعدات والأعضاء كما هي.

ملاحظة: لتسريع السيناريو تُستخدم أداة `devGrant` (مفعلة فقط مع `ALLOW_DEV_CHEATS=1`) لمنح الخبرة/المال بدل لعب ساعات، وكل الانتقالات والتوظيف والعمل الفعلي تتم بمنطق اللعبة الحقيقي.
